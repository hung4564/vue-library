# Accessibility (a11y)

Polish notes for keyboard and assistive-tech support in `@hungpvq/draggable` shells.

Related: [Stable API](./stable-api.md) · [ContextMenu](./context-menu.md) · [CSS tokens](./css-tokens.md)

## Modal (`DraggableModal`)

- `role="dialog"` + `aria-modal="true"` + `aria-labelledby` (header title id)
- Focus moves into the dialog on open; **restored** to the previously focused element on close
- **Tab** / **Shift+Tab** trapped inside the dialog (`trapTabKey`)
- **Escape** closes
- Background siblings under `.draggable-root` get `inert` + `aria-hidden` while open (reference-counted for nested modals)

## Context menu (experimental)

- `role="menu"` + `aria-orientation="vertical"` + `aria-label`
- Items: `role="menuitem"`, `aria-disabled`, `aria-current` when `active`
- **Escape** closes and **restores focus** to the opener
- Arrow **Up/Down** (and Left/Right aliases), **Home/End**, **Enter/Space**
- **Typeahead**: printable characters jump to the next matching label (buffer resets after 500ms)
- Switcher triggers (sidebar / bottom) set `aria-haspopup="menu"` and `aria-expanded`

## Sidebar / bottom shells

- Sidebar: `role="complementary"` + `aria-labelledby` title host
- Bottom: `role="region"` + `aria-label` / `aria-labelledby`
- Expand / collapse / close controls expose descriptive `aria-label`s; expand toggles set `aria-expanded` and `aria-controls` where applicable

## Core helpers (Stable)

| Helper | Use |
|--------|-----|
| `getFocusableElements` / `focusFirst` / `restoreFocus` | Focus management |
| `trapTabKey` | Dialog tab cycle |
| `setModalSiblingsInert` | Background inert while modal open |
| `getMenuItems` / `handleMenuKeydown` / `clearMenuTypeahead` | Menu keyboard + typeahead |

## Still experimental / incomplete

- Full WAI-ARIA **menu button** pattern with owned `aria-controls` id on every trigger
- Submenus and bidirectional typeahead locales
- Drawer Escape-to-close (app-dependent; not default)
